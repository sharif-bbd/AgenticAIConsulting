# Issue Tree (Logic Tree / Problem Decomposition)

## What it is
An issue tree is the foundational tool of McKinsey-style structured problem solving. It decomposes a complex, fuzzy problem into a mutually exclusive, collectively exhaustive (MECE) set of sub-questions or hypotheses. Each branch represents a distinct possible cause, lever, or dimension of the problem. The tree forces clarity: you cannot act on "we need to improve efficiency" — but you can act on "we have excess costs in category X, driven by lever Y."

## When to use it
- The client's problem is ambiguous ("we need to do something about AI", "our costs are too high")
- Multiple possible root causes exist and need to be ruled in or out
- The engagement requires hypothesis-driven work rather than exhaustive analysis
- You need to design a workplan that prioritizes the highest-value investigations first

## Consulting language
In proposals, issue trees are referenced as: "We will structure our analysis around a set of key hypotheses…", "Our approach will be hypothesis-driven, testing the following propositions in order of priority…", "We will decompose the problem into its core dimensions before allocating analytical resources…"

## Customization guidance
- Never show a generic 3-level tree. Always label branches with the client's actual business dimensions (e.g., "RtB vs CtB cost split" not "Cost Category A")
- The top-level question should be the exact "Question to be Answered" from the problem statement section
- Prune branches that context makes clearly irrelevant — a MECE tree with 4 branches is better than 8 with 3 that cannot possibly be the answer
- The tree becomes the skeleton of the Methodology section: each main branch = one work stream

## Example deliverables in a proposal
- "A prioritized list of hypotheses addressing [client problem], with clear criteria for validation or rejection"
- "An issue tree decomposing [problem] into its structural levers, forming the basis of the analytical workplan"
- "A MECE decomposition of potential efficiency improvement measures, spanning [dimension 1], [dimension 2], and [dimension 3]"
